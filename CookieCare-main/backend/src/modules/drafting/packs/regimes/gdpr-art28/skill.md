# GDPR Article 28 — Processor obligations skill

## Applicability
Applies when the deal involves GDPR-style processor obligations (DPA, EEA/UK/Ireland governing law, or EU/EEA processing).

## Required facts
- Where personal data is transferred outside the EEA, the DPA must specify the transfer mechanism (e.g. Standard Contractual Clauses) and, if SCCs are used, identify the applicable SCC module. If facts show an EEA→non-EEA transfer without sccModule/transferMechanism, ask which SCC module applies (Module 2 controller-to-processor vs Module 3 processor-to-processor) — the transfer mechanism clause cites a specific SCC module; drafting the wrong one misstates the parties' actual data-transfer relationship.

## Mandatory requirements
- The processor must act only on **documented instructions** of the controller (Art. 28).
- Persons authorised to process personal data must be under an appropriate **confidentiality** obligation.
- The controller must have **audit / information rights** to verify compliance (may be warning-level if framed as best practice access rather than a hard statutory must-have for every draft variant).
- **Sub-processor flow-down**: any sub-processor must be bound by data-protection obligations equivalent to those in the DPA (flow-down of Art. 28 duties).
