## dpdpa/skill.md

### When this applies
A party processes personal data on behalf of another party for offering goods or services to Data Principals, and the user asked for the Digital Personal Data Protection Act, 2023 (India), or set governing law to India.

Use DPDPA terms: Data Fiduciary, Data Processor, Data Principal, and personal data. Do not use controller, processor, or data subject unless the user also asked for GDPR or another regime that uses those terms.

### Requirements
- MUST engage the Data Processor only under a valid contract for processing on behalf of the Data Fiduciary. (s.8(2))
- MUST limit processing to the Data Fiduciary's documented instructions and the specified purpose. The Data Processor must not determine purposes or means, and must not process personal data for its own purposes. (s.8(2))
- MUST require persons authorised to process personal data to keep it confidential.
- MUST require reasonable security safeguards to prevent personal data breach. (s.8(5)) Do not invent a statutory technical-standard checklist; describe safeguards as a contractual implementation of the Fiduciary's s.8(5) duty.
- MUST require the Data Processor to notify the Data Fiduciary of a personal data breach without undue delay, with information the Fiduciary needs to intimate the Board and each affected Data Principal. (s.8(6)) The statutory intimation duty sits on the Data Fiduciary. Do not state a fixed hour count as a statutory must; a short contractual window is a SHOULD only if the user asked for one.
- MUST, at the Data Fiduciary's choice, erase or return personal data when the specified purpose is no longer served, consent is withdrawn, or the contract ends, and delete copies unless retention is required by law. (s.8(7))
- MUST require the Data Processor to assist the Data Fiduciary with Data Principal rights: access to a summary and identities of processors (s.11), correction, completion, updating, and erasure (s.12), and grievance redressal (s.13).
- MUST require any further processor to be engaged only under a written contract imposing equivalent obligations. The Data Fiduciary remains responsible to the Data Principal. Do not copy GDPR Article 28(2) prior-authorisation wording as if it were a DPDPA statutory rule; frame sub-processor control as a contractual condition of the s.8(2) engagement.
- MUST restrict cross-border transfers: personal data may be transferred outside India except to any country or territory restricted by the Central Government. (s.16) Do not attach EU Standard Contractual Clauses, a UK IDTA, or an adequacy decision unless the user also asked for that regime.
- SHOULD require the Data Processor to make available information reasonably necessary to demonstrate compliance with this contract, and to allow audits on reasonable notice.
- SHOULD note that notice and consent (ss.5–6) remain Data Fiduciary duties. The Data Processor assists; it does not give notice or take consent in the Fiduciary's place.
- Flag: if the processor determines purposes or means itself, it is a Data Fiduciary for that processing, not a Data Processor.

### Conditional — only if the user says they apply
- Children's data (s.9): verifiable parental consent and no processing likely to cause detrimental effect, tracking, or targeted advertising directed at children, unless the user states an exemption applies.
- Significant Data Fiduciary (s.10): Data Protection Officer, independent data audit, and periodic data-protection impact assessment only when the user says the Data Fiduciary is a Significant Data Fiduciary. Do not impose these on an ordinary processor engagement.
